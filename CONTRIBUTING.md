# Contributing to ZMS Labs projects

Use the repository's own contribution instructions when they exist. This is the fallback guidance for projects without a local guide.

1. Read the README, current status, and relevant design or usage documentation. For a fork, check which changes belong here and which belong upstream.
2. Keep the change focused on an identifiable problem. Discuss a substantial change in the relevant issue tracker before investing in a different direction.
3. Follow the project's existing style, licensing, attribution, and sign-off requirements. Add or update documentation when behavior or usage changes.
4. Run the checks appropriate to the change and state what you verified. Distinguish a local result from a deployed or live-observed outcome.
5. Open a pull request explaining the problem, resulting behavior, verification, and any remaining limitation.

Use synthetic examples and minimal reproductions. Do not include credentials, personal information, confidential material, private endpoints, or data you are not authorized to disclose in issues, commits, screenshots, or pull requests.

For documentation changes, use the [documentation standard](https://github.com/ZMS-Labs/.github/blob/main/docs/documentation-standard.md). Repository-specific requirements take precedence over this shared guidance.
