# Finding help

Start with the relevant repository's README and linked documentation. Check its status, limitations, and existing issues before reporting a problem.

For a public technical question, use that repository's issue tracker if it is enabled. Include the relevant version, expected behavior, observed behavior, and a minimal reproduction with made-up data. For a fork, follow the project's guidance about local changes and upstream support.

Public issues are public records. Keep personal information, credentials, confidential data, and internal system details out of the report.

To report a potential vulnerability, use GitHub's private vulnerability reporting: open the repository's Security tab and choose Report a vulnerability. Where a repository has its own security policy, follow that instead. An archived repository can't take private reports; report those through the Security tab of the [ZMS Labs .github repository](https://github.com/ZMS-Labs/.github/security). Do not post sensitive details to a public issue.

Availability and support scope vary by project. The ZMS Labs forks have their issue trackers turned off. Archived repositories are kept for reference and no longer accept changes; if an archived repository's README names a successor, go there instead.

Questions and conversations are welcome through [my GitHub profile](https://github.com/SternOne).
