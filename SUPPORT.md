# Finding help

Start with the relevant repository's README and linked documentation. Check its status, limitations, and existing issues before reporting a problem.

For a public technical question, use that repository's issue tracker if it is enabled. Include the relevant version, expected behavior, observed behavior, and a minimal reproduction with synthetic data. For a fork, follow the project's guidance about local changes and upstream support.

Public issues are public records. Keep personal information, credentials, confidential data, and internal system details out of the report. Follow the repository's security reporting instructions for a potential vulnerability; do not post sensitive details to a public issue.

Availability and support scope vary by project. Archived repositories are historical references unless their README identifies a maintained successor.
